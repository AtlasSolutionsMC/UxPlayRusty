# C reference fixtures

`reference-vectors.txt` was generated by compiling the unmodified `lib/playfair/modified_md5.c` from `D:\Save\Uxplay\UxPlay` with `generate_reference.c` and calling the exported C function for each fixed block/key pair.

- Source SHA-256: `10035FA90F19F5F977AFBCF2517EBC4D66E6358EA75986F7271CD93CBDE53C1D`
- Compiler: MSYS2 UCRT64 GCC 16.2.0, x86_64 MinGW-w64
- Build flags: `gcc -O3 -march=native modified_md5.c generate_reference.c -lm`
- Host word order: little-endian; the Rust implementation uses `from_ne_bytes` / `to_ne_bytes` so the source's native `uint32_t` word access is explicit.
- The fixture includes the 64 round constants printed by the original C expression, plus zero, ascending, wrapped-pattern, descending, and deterministic xorshift32 inputs. The PRNG seed is fixed in the generator.
- `ffi_link_smoke.c` compiles against the Rust DLL and a renamed copy of the original C symbols. It verifies both C exports, the shadow alias, and output aliasing (`key` is also `output`).

To regenerate, run that command with the reference source path and redirect stdout to `reference-vectors.txt`. The generator itself is kept beside the fixtures so the provenance is auditable. The scalar `rust-anything` recording remains in `../cases.jsonl`; these vectors characterize the pointer-only `modified_md5` export that the generic C recorder cannot capture.

The linked ABI smoke test was built by compiling the reference C source with its exported names renamed (`-Dmodified_md5=reference_modified_md5 -Dswap=reference_swap`, and matching renames for `F`, `G`, `H`, `I`, and `rol`), then linking `ffi_link_smoke.c` against `libmodified_md5_rs.dll.a` and `-lm`. It passed with: `C ABI matches reference for swap, modified_md5, and aliased output`.
